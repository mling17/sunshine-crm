> 天窗天幕 CRM V1 · 2026-10-29

## 1. 交付物清单

| 文件 | 作用 |
|---|---|
| `static/index.html` | 单页壳：顶栏导航（看板/客户/商机/跟进/统计/导入）、登录表单、`<main id="app">` |
| `static/app.js` | hash 路由 + 6 个视图 + `api()` 封装（`credentials:'include'`） |
| `static/app.css` | 移动优先响应式样式（桌面 4 列 KPI，手机 2 列） |
| `static/manifest.json` | PWA：`start_url=/crm/`、192/512 图标、standalone |
| `static/sw.js` | 极简 service worker：静态壳 network-first，**不缓存 `/crm/api/`** |
| `static/icons/*.png` | 192 / 512 / maskable-512 图标（由 `ops/make-icons.py` 生成，纯 stdlib） |
| `ops/make-icons.py` | 图标生成脚本（改配色/图形改这里，别手改 PNG） |
| `ops/deploy-frontend.sh` | 复制到 nginx 目录 + 自检（不改 nginx 配置） |

页面/组件：

- **看板**：本月成交（单数 + 金额）、待跟进数、客户总数/本月新客、老客数；今日待跟进列表（含逾期天数、商机阶段标签、一键「记跟进」）；商机阶段分布条。
- **客户**：搜索（姓名/电话/楼盘，300ms 防抖）、标签 chips 筛选、分页（20/页）、新增客户表单（含标签）、客户卡片（老客标记、商机数、累计成交）。
- **客户详情**：档案 + 编辑/删除（级联）、商机列表（`<select>` 改阶段）、新增商机、跟进记录（含照片缩略图、删除）。
- **商机**：按阶段筛选、列表内 `<select>` 直接改阶段、新增商机表单。
- **跟进**：全量列表（客户名/阶段/照片）、新建跟进（客户→商机联动、可选顺手改阶段、`<input type=file accept="image/*" capture="environment" multiple>`，前端卡 3 张/20MB）。
- **统计**：客户总数、本月新客、本月成交、老客（`repeat_customers`）+ 阶段分布 + 口径说明。
- **导入**：CSV 上传 → 表头/前 5 行预览 → 逐列映射（自动建议 + 「用上次映射」）→ `preview` 的 `file_ref` 直接 commit；`.xlsx` 显示「另存为 CSV」提示。

## 2. 部署

```bash
# 一条命令：复制 + 自检（幂等，可重复执行）
bash /opt/data/crm/ops/deploy-frontend.sh

# 等价手动命令
mkdir -p /root/nginx/html/crm
cp -r /opt/data/crm/static/. /root/nginx/html/crm/
```

**不改 nginx 配置**（`/crm/` 的 location 由 T9 合入）。文件落到
`/root/nginx/html/crm/`（容器内是 `/usr/share/nginx/html/crm/`）。

当前实测：nginx 默认 root 已能直接吐出静态文件（`/crm/` 200），但
**`/crm/api/crm/...` 在 T9 合入反代前会 404** —— 此时页面能打开、登录会提示连不上，
属预期，不是前端 bug。

### 变更后的发版流程

1. 改 `static/` 下文件；
2. `bash ops/deploy-frontend.sh`；
3. 手机/电脑强制刷新（`sw.js` 是 network-first，在线时自动拿新文件；`index.html` 由 T9 的
   nginx 片段设 `no-cache`）。

## 3. 路径对齐（最容易写错的地方）

| 层 | 路径 |
|---|---|
| 浏览器页面 | `/crm/#/customers/3`（**hash 路由**，刷新永远命中 `/crm/index.html`） |
| 前端 API 常量 | `const API_BASE = '/crm/api/crm'`（**绝对路径**） |
| nginx 对外 | `/crm/api/crm/<x>` → 正则去掉 `/crm` → `:8010/api/crm/<x>` |
| 后端实际路由 | `APIRouter(prefix="/api/crm")` |

为什么用 hash 路由：`/crm/` 是 nginx 的静态 alias，没有 history fallback；
路径路由（`/crm/customers/3`）一刷新就 404。hash 路由不依赖服务端改写。

图片 URL：后端 `AttachmentOut.url` 返回 `/api/crm/attachments/<id>`，
前端统一拼 `/crm` 前缀 → `/crm/api/crm/attachments/<id>`（带 Cookie，需登录）。

## 4. 登录「电脑端不允许保存密码」

`static/index.html`：

```html
<form id="loginForm" autocomplete="off" novalidate>
  <input id="loginUser" name="username" type="text" autocomplete="off" ...>
  <input id="loginPass" name="password" type="password" autocomplete="new-password" ...>
</form>
```

- 表单级 `autocomplete="off"` + 密码框 `autocomplete="new-password"`：
  普通 `off` 在密码框会被 Chrome/Edge 忽略，`new-password` 才会让浏览器**不弹**「保存密码」。
- 账号框同样 `off`（避免浏览器把它当登录表单联想填充）。
- 密码只存在于该 input 的内存值里：登录成功后立刻 `passEl.value = ''`，
  **全文件没有任何 `localStorage` / `sessionStorage` 读写**（部署脚本会 grep 拦截）。
- 登录失败（401）提示固定为「账号或密码错误」（后端不区分账号错/密码错）。

手动验证：Chrome → 地址栏钥匙图标 → 「从不保存此网站」；或登录后关闭标签页再打开，
输入框应保持空白、无已存密码下拉。

## 5. PWA（添加到主屏幕）

- 入口：`http://<内网服务器IP>:8000/crm/`（**必须走域名/IP + 端口，不能用 file://**）。
- Android Chrome：右上菜单 →「添加到主屏幕」/ 底部安装提示条。
- iOS Safari：分享 → 「添加到主屏幕」（用 `apple-touch-icon`）。
- 安装条件：manifest（name/start_url/display/icons 192+512）+ HTTPS 或 localhost。
  **内网 HTTP 下 iOS/Chrome 可能不给安装**，等 T9 的 HTTPS 或直接「添加到主屏幕」快捷方式。
- 缓存策略：`sw.js` 对 `/crm/` 下的 GET 走 network-first（在线拿最新、断网回退缓存壳），
  显式跳过 `/crm/api/`，客户数据不进缓存。

## 7. 回滚

前端是纯静态文件，回滚只需换回上一版：

```bash
cd /opt/data/crm
git checkout <上一版 commit> -- static/       # 或 git revert <commit>
bash ops/deploy-frontend.sh
```

若整站要下线：`rm -rf /root/nginx/html/crm`（T9 之后还需注释掉 nginx 的 `/crm/` location 并 reload）。
**不要**动 `/root/nginx/html/kb`、`/root/nginx/html/learning-kb`。

## 8. 已知边界（V1 明确不做）

- 不做拖拽看板（改阶段用 `<select>`）；不做多用户/权限；不做推送提醒；不做复杂报表。
- `.xlsx` 不解析：Excel 里「另存为 CSV」再导入（V1.5 才上 openpyxl）。
- 微信内置浏览器不做 UA 检测/机型引导（等用户报机型，V1.5 收敛）；iOS 微信可能屏蔽相册，
  建议「在浏览器打开」。
- `capture="environment"` 会让部分安卓机直接调起相机（一次一张）；要连拍多张时用相册选择。
- 跟进照片 HEIC：能存能回，但浏览器 `<img>` 未必能解码（V1.5 按机型转码）。
- 客户详情页只显示最近 20 条跟进（后端详情接口的上限）。

## 9. 关于 Dockerfile / docker-compose

本项目定稿的部署形态是**系统 python3 单进程 uvicorn（8010）+ 既有 nginx 容器做静态与反代**，
实施计划 §2.3/§2.5 明确「不加任何容器/中间件」。因此 T8 **不提供 Dockerfile / docker-compose**：
前端是静态文件，复制进既有 nginx 目录即可，另起容器只会多一层维护成本。
真要走容器化，改动点在 T9 的部署单元（`ops/crm-api.service` 换成 compose 服务），不是本任务。
