> 用途：这份文档是「每个模块的页面应该长什么样」的唯一依据。
> 业务部分由用户拍板（编号 D/Q），技术方案由 Planner 出，Coder 照此实现。
> 状态标记：✅定稿 ｜ 🟡待你拍板 ｜ ⬜未开始

## 0. 总则（全站统一）

### 0.1 页面骨架（每页都套这 6 段）

| 段 | 要求 |
|---|---|
| ① 入口 | 主导航最多 7 项，其余收进「更多」 |
| ② 列表 | 一行 3–5 个关键字段，手机竖屏一屏 ≥6 行 |
| ③ 筛选 | 搜索框 + 状态页签/下拉，默认落「常用」 |
| ④ 详情 | 分块：基本信息 / 关联 / 历史，一屏内看完，不横向滑动 |
| ⑤ 操作 | 主按钮 1 个（右下角悬浮），次要操作收进「⋯」 |
| ⑥ 空态 | 没数据时说清「下一步做什么」，带按钮 |

### 0.2 导航（D5 ✅定稿）

主导航 7 项：**工作台 / 线索 / 客户 / 商机 / 订单 / 售后 / 更多**

「更多」内：物流、跟进记录、统计、数据字典、导入

### 0.3 金额隐私（D4 ✅定稿，范围见 Q6）

- 金额默认**遮罩显示**（`¥••••`），右侧一个 👁 小眼睛；
- 点 👁 → 显示真实金额，再点 → 恢复遮罩；
- 遮罩状态**切页面保持**（同一会话内记住），重新登录或主动点击才恢复。

### 0.4 口径总则

- 所有日期按**服务器本地时区（Asia/Shanghai）**，不用 UTC 换算；
- 「本月」= 本地自然月 1 日 00:00 至现在；
- 被业务数据引用的主数据（物流公司、字典项）**只能停用，不能删除**。

## 1. 模块① 工作台（✅ 规格定稿）

> 定位：**打开就知道今天该干什么**，不是数据大屏。

### 1.1 页面结构（从上到下，顺序即优先级，D1 ✅定稿：跟进优先）

| 区域 | 内容 | 交互 |
|---|---|---|
| **A. 数字卡** | ①今日待跟进 ②逾期未跟进（红字）③进行中商机（单数+金额）④本月成交额 ⑤**本月新增客户**（D2 ✅定稿新增） | 点卡片 → 跳对应列表并带好筛选条件 |
| **B. 今日待跟进**（核心区） | 每行：客户名 · 意向等级 · 上次跟进日期 · 下次跟进日（逾期整行标红）· 商机阶段 | 行尾「记一条」→ **弹输入框原地记录，不跳页**；点客户名 → 客户详情 |
| **C. 订单待办** | 按状态分组计数：待支付 / 已付押金 / 生产中 / 已付尾款 / 待发货 / 已发货 / 已完成（只显示有数的） | 点数字 → 订单列表对应状态 |
| **D. 最近动态**（10 条，时间倒序） | 「10-31 09:12 张三 · 记了一条跟进」「10-30 16:40 李四订单 → 已付押金」 | 金额走 0.3 隐私遮罩 |
| **E. 空态** | 「还没有客户，先做这三件事」+ ①录第一个客户 ②建第一个商机 ③记第一条跟进（三个按钮） | — |

### 1.2 逾期口径（D3 ✅定稿）

**定义**：某客户**最近一条跟进记录**的「下次跟进日期」≤ 今天，且该客户关联商机未赢单/未流失，即为待跟进；`今天 - 下次跟进日 > 0` 即「逾期 N 天」。

> ⚠️ 现状不一致（必须改后端）
> 现在 SQL 是「所有历史跟进记录中 next_date ≤ 今天」都算待跟进。
> 后果：10-29 记的跟进写了「下次 10-31」，10-30 又记了新跟进写了「下次 11-05」，
> 那条 10-29 的旧记录**会永远挂在待跟进里，永不消失**。
> 正确做法：**按客户取最近一条**跟进的 next_date 再判断。

### 1.3 验收标准

- [ ] 数字卡 5 个，数字与对应列表条数一致
- [ ] 逾期条目整行标红，且「逾期 N 天」天数正确
- [ ] 同一客户记了新跟进后，旧的待跟进自动消失
- [ ] 「记一条」在弹窗内完成，提交后本页自动刷新
- [ ] 一屏（手机）能同时看到 A 区数字卡和 B 区前 3 条待跟进
- [ ] 金额默认遮罩，点 👁 后显示

## 2. 模块⑧ 数据字典（🟡 业务规格草案，待拍板）

### 2.1 为什么要它

现在系统里所有「选项」都**写死在代码里，前后端各写一份**：
- 前端 JS 硬编码下拉（来源、意向等级、客户类型、售后类型…）
- 后端 `enums.py` 又用 `Literal` 硬校验一遍

带来的两个实际问题：
1. **你改不了**：想加一个来源「抖音」、加一个流失原因「工期太长」，必须改代码重新发版；
2. **必然不一致**：这次商机阶段就是后端改了 5 个新阶段、前端还在用旧的 9 个，导致商机页/跟进页全错。

数据字典就是把这堆选项**搬到页面上，你自己能看、能改**。

### 2.2 字典分级（关键规则，Q7 待你确认）

| 级别 | 你能做什么 | 包含哪些字典 | 理由 |
|---|---|---|---|
| **A 可自由增删改** | 新增 / 改名 / 排序 / 停用 | 客户来源、意向等级、流失原因、售后类型、跟进方式、标签 | 纯业务标签，加一个不影响任何流程 |
| **B 只能改显示名 + 排序** | 改名、调顺序，**不能增删** | 商机阶段、订单状态、售后状态 | 它们是状态机，加一个系统不知道下一步该怎么走 |
| **C 只能改显示名** | 改名 | 客户类型（个人/公司） | 背后绑定「公司名是否必填」等逻辑 |
| **D 只读展示** | 只能看 | 跟进对象类型、物流方式、订单状态机顺序 | 系统性定义 |

### 2.3 页面结构

**入口**：更多 → 数据字典

**页面一：字典总览（只读）**
一张表列出系统里所有字典：字典名 / 类型（业务/状态机）/ 选项值 / 中文名 / 被引用条数 / 可否编辑。
作用：随时能看清「系统里到底有哪些选项」，我们沟通时说「改第 3 行」就行。

**页面二：单张字典编辑（A 类才可编辑）**
| 列 | 说明 |
|---|---|
| 值（key） | 新增时填，**保存后不可改**（历史数据靠它） |
| 显示名 | 随时改，前端立即生效 |
| 排序 | 拖动或填序号，决定下拉顺序 |
| 启用 | 停用后新建单不显示，历史数据仍正常显示中文名 |
| 被引用 | 显示 N 条业务数据在用 |

**规则**：
- 被引用 >0 的选项：**禁止删除**，只能停用（沿用「被引用的物流公司禁止删除」的口径）；
- 停用的选项不出现在任何新建/编辑下拉里，但列表和详情照常显示它的中文名；
- 改显示名后，所有历史数据的显示文案立即跟着变（数据里存 key，不存中文）。

### 2.4 关于「产品类型 / 型号」

现状：**这两个字段已经是自由文本输入**（`天窗 / 天幕` 只是占位提示），你填什么都能存。
所以这块现在就不受限，但也因此容易出现「天窗」「天窗框」「推拉天窗」三种写法，统计时被算成三类。

可选方案（Q8 待你定）：
- **方案甲（保持现状）**：继续自由填写，最快，但统计口径会散；
- **方案乙（推荐）**：产品类型改成下拉 + 可新增（走数据字典 A 类），型号保持自由填写。录入时少打字，统计能汇总。

### 2.5 验收标准

- [ ] 新增一个来源「抖音」，客户表单下拉里立刻出现，无需发版
- [ ] 把一个已停用的来源改中文名，历史客户列表里显示的文字跟着变
- [ ] 被引用的来源点删除 → 按钮不可用并提示「有 N 条数据在用，只能停用」
- [ ] 商机阶段只能改名，页面上没有「新增阶段」按钮

## 7. v2.1 定稿（2026-10-31 用户逐模块口述，Demo 已按此重做）

> Demo 入口：**http://10.113.9.77:8000/crm/demo/**（v2.1，仍为 mock，不连后端）

### 7.1 顶部菜单（9 项，定稿）

工作台 · 线索 · 客户 · 商机 · 订单 · 售后 · 物流 · 统计 · 数据字典

（原「跟进」「更多」「导入」不再单列：跟进下沉到线索/客户/商机各自页面；导入并入线索页）

### 7.2 工作台

按上一版设计（§1）不变：5 个数字卡 + 今日待跟进 + 订单待办 + 最近动态 + 空态引导。

### 7.3 线索（表格）

**列表字段**：名称 · 来源 · 地区 · 微信号 · 联系方式 · 标签 · 意向（高/中/低/无，**新建默认「中」**）· 上次跟进时间 · 创建时间 · 操作

**操作**：编辑 ｜ 跟进 ｜ 转商机

**顶部按钮**：＋ 新增线索 ｜ ⇪ 批量导入 ｜ ⬇ 导入模板下载

- **编辑**：改基本信息（名称/类型/手机/微信/地区/公司/来源/来源补充/意向/标签/备注）
- **跟进**：打开新页面 → 顶部卡片显示线索信息 + 操作，下方是跟进履历（时间/内容/方式/下次跟进/附件），可继续记一条
- **转商机**：进入「新建商机」页面（见 7.5），表单含：产品类型、**手动/电动**、**产品型号（下拉）**、尺寸、金额、定金、尾款、阶段
- **批量导入**：下载模板 → 填好 → 上传 → 预览 → 确认；模板列：名称/类型/联系方式/微信号/地区/公司名/来源/意向/标签/备注

### 7.4 客户（表格，不提供新增）

**规则**：客户由线索转化而来，**页面上没有「新增客户」按钮**，只显示「客户由线索转化，不在此新建」。

**列表字段**：名称 · 类型 · 地区 · 微信号 · 联系方式 · 标签 · 意向 · 商机数 · 累计成交 · 创建时间 · 操作

**操作**：编辑 ｜ 跟进 ｜ 转商机

- **编辑**：细化客户信息 + 维护**客户画像**（房屋类型 / 楼层 / 安装位置 / 装修阶段 / 预算 / 决策人 / 关注点）
- **跟进**：与线索跟进同一套页面（信息卡 + 跟进履历 + 记一条）
- **转商机**：同线索转商机

### 7.5 新建商机（由线索/客户「转商机」进入）

| 字段 | 类型 | 说明 |
|---|---|---|
| 产品类型 | 下拉 | 取数据字典 |
| **手动 / 电动** | 下拉，必填 | 用户新增的关键属性 |
| **产品型号** | 下拉，必填 | 取数据字典；选中自动带出尺寸 |
| 尺寸（宽×高） | 文本，必填 | 可手改 |
| 金额 | 数字，必填 | |
| 定金 / 尾款 | 数字 | 只提示「定金+尾款≠金额」，不拦截 |
| 阶段 | 下拉 | 默认「报价」 |

线索转商机 = 线索转客户（自动建档，画像为空）+ 建商机；线索状态变「已转化」。

### 7.6 商机

**列表字段**：客户 · 产品 · 型号 · 手动/电动 · 尺寸 · 金额 · 阶段 · 更新时间 · 操作（跟进 / 生成订单）

**跟进页（新页面）**：
- 顶部：商机基本信息（客户、产品、型号、手动/电动、尺寸、金额、定金、尾款、阶段、创建/成交时间）
- 下方：**跟进履历**，可上传附件（图纸/现场照片/报价单）
- **基本信息一旦变动（尺寸/金额/型号/手动电动…），系统自动生成一条「信息变更」履历**；阶段变化也自动记一条
- 客户认可方案后点 **生成订单** → 模态框（见 7.7）
- **生成订单后商机锁定，不可再修改**（编辑按钮禁用，改为「查看订单」）

### 7.7 生成订单（模态框）

- **继承商机最新信息**（只读展示）：客户、产品/型号、尺寸、手动/电动
- **可确认**：订单金额（默认=商机金额）
- **需新填**：物流方式（物流公司 / 自送）、承运公司（下拉，取物流主数据）、收件人、收件电话、收件地址、运单号（可后补）、备注
- 生成后：订单状态 = 待支付；商机 → 赢单 + 锁定；履历自动记一条「生成订单」；对应物流公司关联次数 +1

### 7.8 订单 / 售后

按既定工作流（订单 7 态：待支付 → 已付押金 → 生产中 → 已付尾款 → 待发货 → 已发货 → 已完成；售后 SLA 3 天）。

### 7.9 物流

列表字段：公司名称 · 联系人 · 电话 · 备注 · **被订单关联次数** · 操作（编辑 / 停用启用 / 删除）
- 被关联次数 > 0 的公司：**删除按钮禁用**，只能停用（历史订单仍显示原名）
- 顶部显示「共被订单关联 N 次」

### 7.10 统计 / 数据字典

按现有设计不变（统计：客户总数/本月新客/本月成交/老客 + 阶段分布 + 口径说明；数据字典：12 张，A/B/C/D 分级）。

## 9. v2.2 定稿（2026-10-31 第二批，Demo build 20261031c）

### 9.1 跟进（通用，线索/客户/商机/售后共用）

### 9.2 商机

- **列表操作只保留「跟进」**；「生成订单」在跟进页里。
- **转商机表单**：产品类型、手动/电动、产品型号（下拉）、尺寸、金额。**不再有定金/尾款**，**初始阶段固定为「报价」**。

### 9.3 生成订单（模态框）

| 区块 | 内容 |
|---|---|
| 继承（只读） | 客户、产品/型号、尺寸、手动/电动、订单总额 |

### 9.4 订单

- 列表：订单号/客户/产品/总额/**押金/尾款**/物流方式+运费/状态/创建时间/详情。

- **完成状态（已完成）才允许「添加售后」**；未完成时按钮禁用并提示。

### 9.5 售后

### 9.6 物流

- 列显示首个联系人 + `+N`，并有「被订单关联 N 次」；被引用只能停用不能删除。

### 9.7 统计（加了图表）

## 15. Q-A…Q-D 拍板决议（2026-10-31，用户确认）

| # | 问题 | 决议 |
|---|---|---|
| Q-A | 型号带出的尺寸能不能手改？统计按型号还是按实际尺寸 | **允许手改；统计一律按实际尺寸**（型号只带出初值、供筛选） |
| Q-B | 售后「已拒绝」状态怎么处理 | **保留可读、不可再写入**；页面不显示该状态，也不再提供拒绝操作 |
| Q-C | 金额遮罩要不要跨天记住 | **只在本次登录会话内记住**，重新登录恢复遮罩 |
| Q-D | 收款金额和应收不一致怎么办 | **不允许不一致：订单金额必须恒等于「押金 + 尾款」** —— 押金填写后尾款自动算；收款金额必须等于应收，否则提示「押金应收 ¥X，实收 ¥Y」并拒绝提交；押金+尾款没收齐不能标记订单完成 |
