## 1. 定位与边界

**V2 是 V1 的演进，不是重写**：在现有系统上新增模块、扩展现有实体字段。

V2 新增/变更：

| 模块 | 相对 V1 |
|---|---|
| 线索管理 | **全新**（V1 无线索，客户靠手工建/CSV 导入） |
| 客户管理 | 扩展：客户类型、来源、意向等级、公司多联系人 |
| 商机管理 | 演进：阶段枚举重定、去掉概率、赢单生成订单 |
| 订单管理 | **全新** |
| 售后管理 | **全新** |
| 物流管理 | **全新**（主数据 + 订单物流记录） |
| 工作台 | V1 首页看板演进：今日待跟进 + 订单状态总览 + 最近订单 |

**边界（明确不做）**：
- 多用户、公海池、角色权限（仅预留字段）
- 生产排程/工单（"生产中"只是订单状态标记，系统外完成）
- 财务流程（财务确认是系统外操作，系统只记录结果）
- 多日日程/提醒订阅（仅今日+逾期）
- 发票、合同、收款凭证管理（仅押金/尾款截图上传）

## 2. 总体业务流程

```
线索(新建/跟进/意向记录)
   │  建商机（意向等级仅参考，不校验）
   ▼
客户 + 商机（线索归档；档案/跟进记录/意向等级全部迁移）
   │  商机跟进、阶段推进
   ▼  赢单（一对一生成订单，订单总额=商机金额）
订单：待支付 → 已支付押金 → 生产中 → 已支付尾款 → 待发货 → 已发货 → 已完成
   │  （各跃迁动作见 3.4）
   ▼  产生问题
售后单（退货/换货/维修/投诉/其他）：待处理 → 处理中 → 已完成/已拒绝

辅助流：老客户 → 客户页直接新建商机 → 重复 商机→订单 循环
主数据：物流公司 CRUD → 订单创建时选择
聚合读：工作台（今日待跟进/订单总览/最近订单）
```

## 3. 模块规格

### 3.1 线索管理

**字段**
- 联系信息：手机号、微信号（至少填一个才能创建）
- 类型：个人 / 公司（公司线索加：公司名）
- 来源：微信 / 电话 / 转介绍 / 老客户 / 其他（固定枚举+其他自由文本）
- 地区（楼盘/安装地址，文本）、标签、备注
- 意向等级：高 / 中 / 低 / 无意向（线索级属性，跟进时人工标注；仅参考，无系统门槛）
- 状态、创建时间（转化为客户后客户继承此值）、更新时间

**状态机**：`新线索 → 跟进中 → 已转化 / 已失效`
- 已失效必选原因：无效号码 / 黑名单 / 无意向 / 重复 / 其他

**跟进**：挂在线索上的跟进记录（见 3.8 统一模型）；每次跟进可更新意向等级、设下次跟进时间。

**转化规则**
1. 对线索"建商机"：必填商机名称、产品（类型/型号/规格）、金额
2. 系统生成客户 + 首个商机，线索置"已转化"归档；以下内容**全部迁移**到客户档案：来源、地区、备注、标签、历史跟进记录、意向等级、创建时间
3. 去重：手机/微信命中已有客户 → 提示"客户 XXX 已存在"：
   - 选"关联已有客户"：商机挂到已有客户名下，线索归档（不新建客户）
   - 选"强制新建"：按正常转化流程走
4. 公司线索转化时仅带主联系人；多联系人在客户档案阶段维护（见 I4）

### 3.2 客户管理

**字段（分类型）**
- 公共：类型、地区、标签、备注（新 note 列，Q8：废弃 V1 house_note）、意向等级（继承线索最后值，后续跟进可更新）、来源（继承线索）、创建时间（继承线索）、更新时间、负责人（预留，默认=本人）
- 个人：姓名、手机、微信
- 公司：公司名、**联系人（多条，每条：姓名/手机/微信）**、地区

**生命周期系统标签（自动派生，不可手改）**
- 潜在客户（无商机）/ 商机中（有进行中商机）/ 已成交（有已完成订单）/ 复购（≥2 个已完成订单）

**客户 360 视图（核心页面）**：档案 + 标签 + 商机列表 + 订单列表 + 售后单列表 + 跟进时间线，一页看全。

**操作**：编辑档案、客户级跟进、**新建商机（第 2 个及以后，不走线索）**、进入关联订单/售后。

### 3.3 商机管理

**字段**：商机名称、所属客户、产品（类型：天窗/天幕 + 型号 + 规格尺寸）、金额（报价）、阶段、状态、流失原因（流失时必选）、来源流失商机（可选，重启用）、负责人（预留）
- **无**：预计成交日期、赢单概率（N3）

**阶段（状态流）**：`需求确认 → 报价 → 成交洽谈 → 赢单 / 流失`
- 流失必选原因：价格 / 竞品 / 客户放弃 / 预算不足 / 其他

**跟进**：商机级跟进记录（推动成交的动作），与客户级跟进分开挂，客户 360 可看全部；**仅进行中可添加**（N6/N7）。

**状态冻结规则（N6/N7）**

| 状态 | 可编辑 | 可跟进 | 可创建订单 |
|---|---|---|---|
| 进行中 | ✅ | ✅ | ✅（赢单） |
| 赢单（已绑订单） | ❌ 冻结 | ❌ 跟踪移至订单 | ❌（1:1 已满足） |
| 流失 | ❌ 冻结 | ❌ 可新建商机重启 | ❌ |

- **赢单**：生成 1 张订单（一对一）——订单总额=商机金额（只读），产品信息继承；商机记录成交时间（驱动本月成交统计）。之后所有跟踪在订单上进行（订单跟进记录/状态历史）
- **流失**：必选原因（价格/竞品/客户放弃/预算不足/其他），商机冻结；如需继续，新建商机并可用"来源流失商机"（可选）关联旧流失商机，关联关系在客户 360 可见

### 3.4 订单管理

**字段**：订单号、客户、来源商机（必填，一对一）、产品（继承）、**总额（=商机金额，只读）**、押金金额、尾款金额、押金截图、尾款截图、物流方式（物流公司/自送）、运单号、发货日期、状态、创建时间

**状态流（严格线性，无取消分支 R1）**：

| 当前状态 | 跃迁动作（系统内输入） | → 新状态 |
|---|---|---|
| 待支付 | 填押金金额 + 上传支付截图 | 已支付押金 |
| 已支付押金 | 财务确认（系统外）后点"下一步" | 生产中 |
| 生产中 | 生产完成（系统外）→ 客户付尾款 → 填尾款金额 + 上传截图 | 已支付尾款 |
| 已支付尾款 | 点"下一步" | 待发货 |
| 待发货 | 填物流信息：物流公司 + 运单号（必填，自送填"无"） | 已发货 |
| 已发货 | 标记"客户确认收货" | 已完成 |

**规则**
- 订单**不可手动创建**，只能由商机赢单生成（D3/N6）
- 押金 + 尾款**必须等于**订单总额（强制相等，Q1）
- 每次跃迁写入状态历史日志（操作时间、输入金额、截图引用），不可越级、不可回退
- 自送场景（建单时选"自送"）：待发货跃迁时运单号填"无"
- 退款/退货不是订单状态，一律开售后单（R1）

### 3.5 售后管理

- 由订单发起售后单
- **字段**：售后单号、关联订单、类型（退货/换货/维修/投诉/其他）、描述、状态、处理结果
- **状态流**：`待处理 → 处理中 → 已完成 / 已拒绝`（拒绝需填原因）
- **SLA**：待处理超 3 天未处理 → 工作台红色提醒（N8）
- 售后单**不回写订单状态**（I2）；退款完成与否只记录在售后单内
- 售后终态（已完成/已拒绝）**不可重开**；新问题**新建售后单**；**一个订单可关联多张售后单**（Q4）
- 售后单可挂跟进记录（处理过程沟通）

### 3.6 物流管理

- **主数据层**：物流公司 CRUD（名称、联系人、电话、备注）——用户手工维护（N5）
- **执行记录层**：订单上的物流方式/运单号/发货日期（见 3.4）；物流页提供"物流查询"入口：列出所有订单运单号 + 当前状态

### 3.7 工作台

- **今日待跟进**：聚合 线索/客户/商机/订单/售后 五类的"下次跟进时间"，今日到期 + 逾期（**逾期标红**），点击进对象详情（D8）
- **订单状态总览**：7 个状态的数量 + 金额汇总
- **最近订单**：最新 10 笔列表
- 不做多日日程视图

### 3.8 统一跟进模型

- 跟进记录挂 5 类对象：线索 / 客户 / 商机 / 订单 / 售后单
- 字段：对象、跟进方式（电话/微信/到面/线上）、内容、下次跟进时间、附件（≤3 张，沿用 V1 约定）、记录时间
- 一条跟进只挂一个对象；内容可自由文字提及关联商机（不做强关联）
- 订单/售后的"跟进"= 状态跃迁记录 + 沟通备注，非关系型跟进
- 商机跟进仅在"进行中"可添加；赢单/流失后商机停止跟进（N6/N7）
