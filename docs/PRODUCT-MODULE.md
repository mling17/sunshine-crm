# 产品模块设计（基于 123 份天窗下单表）

## 盘点结果

- 工作簿合计 367 个工作表；部分文件含 `Sheet2`、`Sheet3` 或“带边料 / 不带边”备选页。
- 122 份包含下单日期、单价、金额和备注，120 份包含洞口尺寸，115 份包含收货人及电话，107 份包含收货地址。
- 最稳定的通用列为：序号、产品名称、加工尺寸、数量、宽、高、洞口尺寸、扇制作尺寸、框制作尺寸、玻璃、颜色、单价、金额、收货信息和备注。
- 产品差异主要集中在：系列、平放/嵌入/平起/平移/排水结构、手动/电动、扇数、联排/对开/竖联、带边/不带边、新扇/老扇/高低扇，以及电机罩、纱窗、金刚网、遮阳和把手。

## 设计结论

产品模块采用四层口径：

| 层级 | 负责内容 | 不应混入的内容 |
| --- | --- | --- |
| 产品主档 `products` | 可复用的产品编码、名称、家族、结构、驱动、型材、扇型、规格范围、常用附件，以及该产品唯一的 Excel 下单表 | 某个客户的具体洞口尺寸、成交价、收货地址 |
| 商机关联 `deals.product_id` | 本次销售选择的产品；保存产品名称、编码和配置快照 | 指向可被后续编辑覆盖的唯一产品名称 |
| 订单快照 `orders.product_*` | 从商机复制并在生成订单时冻结的产品凭证 | 每一笔订单都重新读取产品主档 |
| 下单/生产参数 | 宽、高、洞口、数量、现场要求、工厂制作尺寸和公式结果 | 把这些一次性参数反向写回产品主档 |

这种拆分解决两个问题：

1. 产品主档可以持续改名、停用或补充配置，历史商机和订单仍保留成交时的名称、编码和配置。
2. 同一个产品可以服务大量不同尺寸的客户，不需要为每种洞口尺寸复制产品。

## 产品字段

| 字段 | 说明 |
| --- | --- |
| `code` | 唯一、稳定的产品编码；新建立即由服务端顺序分配，初始目录使用 `TS-001` 至 `TS-123`，其后为 `TS-124` 起 |
| `name` | 客户和销售都能理解的名称，优先采用模板标题，而不是文件名 |
| `category` | 天窗、天幕、开合屋面、纱窗、遮阳、配件 |
| `series` | 25 型、55 型、95 型、140 型等 |
| `structure` | 平放、嵌入、平起、平移、排水板、隐藏排水等 |
| `opening_mode` | 单扇开启、联排、对开、高低扇、固定+开启等 |
| `drive_type` | 手动或电动 |
| `frame_type` | 普通、重型、极窄、断桥、隐藏型材等 |
| `leaf_type` | 新扇、老扇、高低扇、大料 |
| `edge_type` | 带边或不带边 |
| `leaf_count` | 扇数 |
| `min/max_width`、`min/max_height` | 可选的可生产范围；未知时留空，不伪造限制 |
| `attributes` | 纱窗、金刚网、电机罩、遮阳、把手、其他配置 |
| `source_template` | 来源模板相对路径，仅作内部追溯 |
| `form_storage_key` | 上传目录中的产品下单表存储键 |
| `form_file_name`、`form_file_size` | 下载时显示的原始文件名和文件大小 |
| `form_sha256` | Excel 文件指纹，用于识别文件替换和损坏 |

## 商机交互

- 新建商机必须先从产品主档选择产品。
- 选择产品后自动带出产品类型、型号（产品编码）和手动/电动；销售只需填写本次洞口尺寸、报价和备注。
- 产品名称、编码和配置摘要写入商机快照。
- 商机生成订单时复制产品快照；之后修改产品主档不改变历史商机和订单。
- 旧商机没有 `product_id` 时仍按原有型号字典编辑，不影响兼容性。

## 文件约束

- 一份 Excel 对应一个产品，产品新增时必须同时上传 `.xlsx` 或 `.xls`。
- 新增页支持“从下单表生成”：上传 `.xlsx` 后先识别标题、系列、结构、开启方式、驱动、扇数及常用配置，确认后再创建产品。产品编码在创建时自动分配。
- 自动识别只使用模板标题与产品特征词，客户尺寸、价格、收货信息和备注不写入产品主档。
- 文件最大值 20MB，服务端校验扩展名和 Excel 文件签名。
- 每份 Excel 保存原始文件名、大小和 SHA-256；产品详情页和列表均可直接下载。
- 文件被替换时保留原产品编码和历史商机/订单快照。
- 没有 Excel 的产品不能启用，也不能在新商机中选择。

## 初始目录

`app/data/order_form_catalog.json` 从模板标题和目录归纳出 123 个可售产品，每个产品对应一份原始 Excel。原始工作簿完整保存在 `app/data/product_forms/TS-001.xlsx` 至 `TS-123.xlsx`，启动时复制到受控上传目录并通过数据库关联。源文件可能包含曾经填写过的示例客户信息，因此上传目录和备份均按内部业务数据保护。

启动迁移会按 `seed_key` 幂等补齐；已存在的产品不会被覆盖，已经删除的种子产品也不会被自动恢复。
