# TC-DEALS 商机页测试记录

## 测试范围

- 商机列表、阶段筛选、排序与空值展示
- 商机详情、客户/订单跳转、跟进履历
- 客户转商机、线索转商机及表单校验
- 商机编辑、型号联动、阶段推进
- 判流失及流失原因校验
- 生成订单的押金/尾款计算，自提、包邮、代办三类物流
- 商机锁定、订单生成后的回写
- 商机跟进入口、跟进保存及履历回写
- 非法路由、不存在资源和浏览器控制台错误

## 缺陷明细

### P1：商机详情的“记跟进”没有携带预期参数

`static/views/deals.js:138` 和 `static/views/deals.js:155` 生成
`#/followups?object=deal&id=...`，但 `static/views/followups.js:62-63`
只读取 `customer` 和 `deal`。实测会带入无关客户，关联商机为“不关联”。

复现：

1. 打开任一商机详情。
2. 点击右上“+ 记跟进”或履历区“+ 记一条”。
3. 观察客户被错误预选，关联商机为空。

### P1：成交/流失商机仍显示跟进入口，但保存必定失败

商机页面始终显示“+ 记跟进”，但 `app/routers/followups.py:225-230` 和
`app/routers/followups.py:335-340` 会拒绝所有 `won` / `lost` 商机的跟进。
由于订单生成后商机固定为成交，正常成单商机都无法再通过该入口记录跟进。

实测提示：`商机已赢单或已流失，无法添加跟进`。

### P1：生成订单后订单详情丢失“物流方式”

自提、包邮、代办三种订单均已生成成功，但订单详情的物流方式都显示 `—`。
接口实际返回 `logistics_mode=agent`、`logistics_mode_label=null`；
前端 `static/views/orders.js:161` 和 `:260` 只读取 label。

### P2：编辑商机的阶段下拉包含“流失”，保存必然报错

`static/views/deals.js:217` 使用 `stageOptions()`，而
`static/views/shared.js:9-13` 无条件输出全部阶段，包括流失。
后端 `app/routers/deals.py:267-273` 规定流失必须走独立操作。

实测选择“流失”后保存提示：`判流失请用「判流失」操作并填写流失原因`。

### P2：流失履历显示内部枚举值

判流失后履历显示 `阶段推进：报价 → 流失（price）`，而详情状态文案显示
“已判流失（价格）”。原因是 `app/routers/deals.py:610-613` 使用原因 key
拼接履历，没有优先使用中文标签。

### P2：锁定/流失商机不能再改备注

后端明确允许已锁定或已流失商机仅修改备注，但
`static/views/deals.js:115-120` 将“编辑商机”整体禁用，页面上没有单独的备注编辑入口，
导致该后端能力不可用。
